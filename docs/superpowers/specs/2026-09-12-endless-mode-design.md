# 无尽模式设计

## 目标

在不改变主线关卡、解锁、星级、图鉴、称号和体力数据的前提下，新增可中断恢复、失败后整轮重置、每关最多一次广告重试的无尽模式。

## 入口与解锁

- 首页左侧新增“无尽模式”入口，使用用户提供的透明 128×128 双倍图，游戏内显示 64×64。
- 入口中心与右侧收藏品按钮保持同一水平线，即复用收藏品按钮的 `y`，左侧使用对称 `x`。
- 入口始终可见且不置灰。主线 `completedThrough >= 5` 时可进入；此前点击只显示“完成第5关后解锁无尽模式”。

## 关卡池与顺序

- 只读取静态 `PUBLISHED_LEVELS`，排除唯一教学关第1关；运行时不生成、不求解关卡。
- 当前工程自动得到第2–150关；未来第151–300关加入目录后自动进入关卡池，不修改无尽逻辑。
- 每轮按章节从低到高推进，每个章节内部使用本轮种子打乱且不重复；遍历全部已发布关卡后开启下一循环并重新打乱。
- 失败并结束本轮后丢弃旧种子；下一轮生成新顺序。

## 步数与失败

- 每关允许步数为：`optimalMoves + max(4, ceil(optimalMoves × tolerance))`。
- 当前连胜1–5关使用25%容错，6–15关使用20%，16关及以上使用15%。
- 只有成功倒药才消耗一步；选择、取消、无效倒入和动画不消耗。
- 最后一步完成关卡优先判定成功；步数耗尽仍未完成时失败；未完成且没有任何合法倒法时立即失败。
- 无尽模式不消耗体力，禁用撤销和额外空瓶；点击重来直接进入失败流程，不能免费重置棋盘。

## 会话与存档

- 使用独立的 `witch-water-sort:endless:v1` 本地记录，不读取或覆盖主线关卡快照。
- 稳定状态下保存本轮种子、循环、关卡序号、来源关卡ID、允许步数、当前棋盘、已用步数、连胜、历史最高连胜、当前关卡是否已使用广告重试以及失败待处理状态。
- 中途返回首页、切后台、关闭小游戏都不算失败；再次进入恢复同一棋盘和剩余步数。
- 失败状态必须先持久化再显示弹窗。失败后杀进程，再次进入仍显示失败弹窗，不能回到失败前。

## 成功、失败与广告

- 完成无尽关卡后连胜加一并保存历史最高连胜；完成页复用现有面板风格，显示当前连胜、历史最高和“下一关”。无尽完成不写主线最佳步数、星级或完成边界。
- 失败弹窗说明：观看广告可从当前关卡初始棋盘重新挑战；返回首页会结束本轮，下次从无尽第1关开始。
- 每个无尽关卡最多一次广告重试。完整观看广告后重置当前关卡和步数上限，保留连胜与关卡位置；取消或广告失败时保留失败弹窗。
- 点击“返回首页”必须二次确认。确认后清除当前轮，只保留历史最高连胜；“无尽第1关”指新一轮的第一关，来源池仍排除主线教学关第1关。

## 界面与现有系统边界

- 首页入口、无尽关卡页、完成页和失败弹窗沿用现有紫金色资源、字体阴影、点击音效、轻震动及弹窗过渡。
- 无尽关卡页显示“无尽 · 第N关”、剩余步数和当前连胜。
- 复用现有棋盘交互与奖励广告端口，不新增依赖，不连接新的服务端接口。
- 主线进度、每日委托、图鉴、称号、体力和云同步对无尽状态无读写依赖。

## 验证

- 核心测试覆盖：排除第1关、章节内确定性随机、步数上限、最后一步成功、耗尽失败、无合法倒法失败、每关一次广告重试、中途恢复、失败状态恢复和结束整轮。
- 平台存档测试覆盖损坏记录回退和与主线键隔离。
- 场景流测试覆盖锁定入口、进入、完成、失败、继续、广告重试和返回首页二次确认。
- 新 PNG 必须导入为 SpriteFrame，并在微信资源索引中出现 `/spriteFrame` 路径。
- 最终运行聚焦核心测试、Cocos Creator 3.8.8 微信构建、微信包准备测试，并从全新开发者工具进程上传预览。
