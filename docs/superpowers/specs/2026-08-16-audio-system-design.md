# 魔女炼金水排序：音频系统设计

日期：2026-08-16  
状态：设计已口头确认，待书面规格复核  
适用范围：当前 React/Vite 交互原型，以及后续 Cocos Creator 3.x 微信小游戏工程

## 1. 目标与已确认决策

本次先完成音效方案与 Web 原型接入，再进入微信小游戏工程化。音频必须加强操作反馈和魔女炼金氛围，但不得改变游戏规则、阻塞操作或显著增加包体。

已确认的产品决策：

- 同时提供循环背景音乐和完整核心操作音效。
- BGM 采用“温暖、神秘的炼金室”方向：柔和钟琴、玻璃泛音和轻微夜间环境声，不使用明显鼓点。
- 音频全部为项目本地原创合成素材，不依赖外部版权素材。
- 使用独立 `AudioDirector` 管理音频；React 与 Cocos 只替换播放适配器，游戏事件契约保持一致。
- BGM 与游戏音效提供独立开关，并保存玩家设置。
- 声音设置入口沿用当前暗紫、金色、Q 版炼金 UI，并使用正式图片资产。

## 2. 范围

### 2.1 本轮包含

- 1 条可无缝循环的炼金室 BGM。
- 10 类核心声音提示，其中通用按钮音可被多个控制复用。
- 浏览器端音频播放适配器和独立音频管理层。
- BGM/SFX 独立开关、淡入淡出和本地持久化。
- 自动播放解锁、前后台切换、并发限制、降级和资源释放。
- 声音设置按钮、紧凑浮层及其正式 UI 图片资产。
- 单元测试、素材完整性校验、构建验证和浏览器试听验收。
- 面向 Cocos Creator/微信小游戏的迁移边界说明。

### 2.2 本轮不包含

- 真实微信广告 SDK；原型只对“奖励空瓶已发放”结果播放奖励音。
- 云端音频配置、远程素材下发、AB 实验或后端音频服务。
- 语音、角色对白、旁白和震动反馈。
- 首页、结算页或更多关卡专属音乐。
- Cocos Creator 工程本身的创建与接入；该工作在 Web 音频验收后另行规划。

## 3. 听觉方向

### 3.1 总体气质

声音需与暗调 Q 版魔法炼金房一致：温暖木质空间作为底色，玻璃、钟琴、微光粒子作为魔法识别层。反馈应柔和、短促、易区分，避免街机式高亮蜂鸣和持续强节奏。

### 3.2 混音原则

- BGM 保持低存在感，默认轨道音量建议为 `0.36`。
- SFX 默认轨道音量建议为 `0.78`。
- 合成成功和奖励音播放期间，BGM 目标音量临时降低 30%，随后在约 300ms 内恢复。
- 同时发声的短音效最多 4 个；超出时优先保留合成、消失和奖励反馈。
- 同一高频声音设置冷却，避免快速点击形成爆音或“机关枪”效果。
- 最终以真机主观试听为准，任何数值均可在不改变事件契约的前提下调音。

## 4. 声音清单与事件映射

| 事件 ID | 使用场景 | 声音设计 | 建议时长 | 冷却/并发 | 视觉同步点 |
|---|---|---|---:|---|---|
| `bgm.alchemy_room` | 关卡常驻背景 | 钟琴、玻璃泛音、轻夜间环境声，无鼓点 | 45–60s 循环 | 单实例 | 首次浏览器用户手势后淡入 |
| `ui.tap` | 声音设置、撤销、重开等通用 UI 触发前反馈 | 短促木质轻敲 | 50–90ms | 60ms；最多 2 | 按钮按下时；若有专属结果音则不重复播放 |
| `bottle.select` | 选中可操作瓶子 | 清脆玻璃轻响＋微弱闪光 | 120–180ms | 80ms；最多 2 | 瓶子抬起、魔女挥杖开始时 |
| `bottle.deselect` | 再次点击源瓶取消选择 | 音高轻微下降的玻璃声 | 100–160ms | 80ms；最多 1 | 瓶子回落时 |
| `pour.valid` | 合法倒入开始 | 液体流动＋细小魔法粒子 | 450–550ms | 100ms；最多 2 | 倒液/粒子动画开始时 |
| `pour.invalid` | 空瓶起手或非法目标 | 柔和软木塞闷响与轻微魔法失效声 | 250–350ms | 120ms；最多 1 | 无效提示与魔女失误反馈出现时 |
| `potion.complete` | 一瓶同色药水合成成功 | 三音阶钟琴上行＋聚合闪光 | 900–1100ms | 不截断；高优先级 | 完成爆发动画 `t=0` |
| `potion.vanish` | 已完成瓶飞离并消失 | 轻柔空气吸走声 | 500–700ms | 最多 2；高优先级 | 爆发前导结束、飞离开始，当前节奏约 `t=300ms` |
| `history.undo` | 撤销成功 | 短促反向魔法闪光 | 180–260ms | 100ms；最多 1 | 棋盘状态恢复后 |
| `level.restart` | 确认重开并完成复位 | 药剂搅动后归位 | 300–450ms | 不叠加 | 新棋盘状态落位时 |
| `reward.empty_bottle` | 广告结果成功并加入空瓶 | 温暖明亮的奖励铃音 | 700–900ms | 不截断；高优先级 | 奖励瓶槽激活时 |

补充规则：

- 游戏逻辑先判定结果，再派发声音事件；不得仅根据点击动作猜测结果。
- 非法倒入只播放 `pour.invalid`，不叠加 `ui.tap`。
- 一次操作同时触发合法倒入和完成时，先播放 `pour.valid`，检测到完成后立即叠加 `potion.complete`；`potion.vanish` 按完成动画时间线延迟触发。
- 撤销不可用、奖励不可用等禁用按钮不播放确认音。
- 重开只在确实完成状态复位后播放专属音。

## 5. 原创素材生产与文件策略

### 5.1 生产方式

- 使用确定性合成脚本生成全部声音，种子、参数和生成命令随项目保存。
- BGM 由钟琴/玻璃音色、柔和和声铺底和低密度环境纹理构成；首尾在节拍、响度和相位上形成可循环边界。
- SFX 由短包络振荡器、噪声、滤波、延迟和混响组合生成，不采样外部商业素材。
- 不在运行时实时合成；运行时只解码和播放已生成的本地音频文件，保证 Web 与 Cocos 行为一致。

### 5.2 文件结构

建议结构：

```text
prototype/public/assets/game/audio/
  bgm/
    alchemy-room-loop.<runtime-format>
  sfx/
    ui-tap.<runtime-format>
    bottle-select.<runtime-format>
    bottle-deselect.<runtime-format>
    pour-valid.<runtime-format>
    pour-invalid.<runtime-format>
    potion-complete.<runtime-format>
    potion-vanish.<runtime-format>
    undo.<runtime-format>
    restart.<runtime-format>
    reward-empty-bottle.<runtime-format>
  audio-manifest.json

prototype/artifacts/audio-masters/
  *.wav
  generation-report.md
```

- `public` 下只保留运行所需压缩文件和清单。
- 无损 WAV 母版、生成报告和试听拼接文件放入 `artifacts`，不进入运行包引用。
- 实施阶段基于浏览器、Cocos Creator 和目标微信小游戏环境的实际解码验证确定运行格式；优先使用单一兼容格式，必要时由适配器选择双格式回退。
- 运行音频总包体目标不超过 2.5MB。

### 5.3 素材清单

`audio-manifest.json` 至少记录：

- 稳定 cue ID；
- 文件路径与内容哈希；
- 时长、声道、采样率；
- 默认增益、冷却时间、最大并发和优先级；
- 是否循环以及循环起止点；
- 生成器版本和种子。

## 6. 技术架构

### 6.1 分层

```text
游戏交互/结果
  -> AudioCue 事件
  -> AudioDirector（平台无关策略）
  -> AudioDriver（平台播放适配器）
  -> 本地音频文件
```

职责边界：

- 游戏规则/引擎：只返回操作结果，不导入浏览器、React、Cocos 或音频 API。
- 事件映射：把已确认的游戏结果映射成稳定 cue ID。
- `AudioDirector`：负责解锁、预加载、BGM 状态、分轨、冷却、并发、ducking、生命周期和释放。
- `AudioDriver`：负责某一平台上的加载、播放、暂停、淡变和销毁。
- UI：只读写玩家设置，并调用 `AudioDirector`；不直接持有音频实例。

### 6.2 平台无关接口

概念接口如下，最终文件名可按现有工程约定调整：

```ts
type AudioCueId =
  | 'ui.tap'
  | 'bottle.select'
  | 'bottle.deselect'
  | 'pour.valid'
  | 'pour.invalid'
  | 'potion.complete'
  | 'potion.vanish'
  | 'history.undo'
  | 'level.restart'
  | 'reward.empty_bottle';

interface AudioDirector {
  unlock(): Promise<void>;
  play(cue: AudioCueId): void;
  startBgm(): void;
  setMusicEnabled(enabled: boolean): void;
  setSfxEnabled(enabled: boolean): void;
  suspend(): void;
  resume(): void;
  dispose(): void;
}
```

`AudioDirector` 的公开调用不返回影响游戏规则的值。播放失败只进入诊断记录，不改变关卡结果。

### 6.3 React 原型接入

- 在原型根组件生命周期内惰性创建一个 director 实例，避免重复渲染创建多条 BGM。
- 第一次瓶子点击或 UI 点击（无论该次游戏操作是否合法）时调用 `unlock()`；解锁成功且音乐开启时淡入 BGM。
- 现有交互处理器在状态变更确认后派发 cue，不把音频调用放入纯游戏引擎。
- 完成动画沿用现有约 1080ms 总时间线：完成判定触发 `potion.complete`，约 300ms 后由受控定时触发 `potion.vanish`。
- 重开和卸载时清除声音定时器；旧操作的延迟回调不得污染新关卡。
- 监听页面可见性：后台 `suspend()`，回到前台且设置允许时 `resume()`。

### 6.4 Cocos/微信小游戏迁移

- 保留 cue ID、manifest、事件映射、默认增益和冷却规则。
- 将 Web `AudioDriver` 替换为基于 Cocos 音频组件/微信运行环境的驱动。
- 设置存储适配器从浏览器本地存储替换为微信小游戏本地存储。
- 真实广告完成回调只派发 `reward.empty_bottle`；广告取消或失败不播放奖励音。
- 音频不依赖后端。未来若改为远程分包或 CDN，下发失败仍需保留包内核心音效回退。

## 7. 设置状态与交互

### 7.1 状态模型

```ts
interface AudioPreferencesV1 {
  musicEnabled: boolean;
  sfxEnabled: boolean;
}
```

- 默认值：`musicEnabled=true`、`sfxEnabled=true`。
- Web 建议使用版本化键 `witch-water-sort.audio.v1`。
- 数据缺失、解析失败或字段非法时回退默认值，不中断页面。
- 关闭音乐后约 300ms 淡出；重新开启时在解锁条件满足后淡入。
- 关闭 SFX 立即停止新的短音效；已经开始的高优先级完成音可快速淡出，避免硬切爆音。

### 7.2 关卡页 UI

- 在右上安全区放置小型声音设置按钮，不遮挡关卡信息、魔女或瓶子区域。
- 按钮采用现有金色/暗紫色图片按钮语言，必须使用正式 raster 资产或项目已有匹配图标库，不使用 emoji、文本符号或 CSS 手绘图标。
- 点击展开紧凑浮层，显示“背景音乐”和“游戏音效”两个独立开关。
- 浮层使用与现有 message 面板一致的暗色炼金边框、柔光和圆角，渐入渐出。
- 点击浮层外部或按 Escape 关闭；切换开关不自动关闭浮层。
- 控件具有可见焦点、语义名称、状态表达和至少 44px 的触控区域。
- 若设备静音、系统拒绝播放或音频未加载，不弹阻断提示。

## 8. 生命周期、错误与性能

- 首屏预加载短小常用 SFX；BGM 异步加载，不阻塞游戏首屏和操作。
- 单素材加载或解码失败时将其标记为不可用，后续调用静默跳过；其他 cue 继续工作。
- BGM 始终保持单实例，重复 `startBgm()` 必须幂等。
- 页面后台、锁屏或系统打断时暂停；恢复后不得出现双重 BGM。
- SFX 全局最大并发为 4。高优先级声音可以淘汰最旧的低优先级声音，反向不可。
- 同 cue 冷却和 voice pool 必须由 director 统一管理，不能散落在 React 组件中。
- director 销毁时停止所有声音、取消淡变和延迟任务、注销生命周期监听。
- 音频异常只在开发诊断中记录；生产体验不显示技术错误消息。

## 9. 验收与测试

### 9.1 自动测试

- 事件映射：选中、取消、合法倒入、两类非法操作、完成、消失、撤销、重开和奖励均得到唯一正确 cue。
- 结果顺序：游戏规则结果先产生，声音随后派发；禁用操作不产生确认音。
- 设置：默认值、读写、版本键、损坏数据回退和 BGM/SFX 独立性。
- director：首次解锁幂等、BGM 单实例、冷却、最大并发、高低优先级、ducking 和恢复。
- 生命周期：后台暂停、前台恢复、重开清理、卸载释放和陈旧延迟回调防护。
- 失败降级：单文件加载失败、解码失败和播放被拒绝均不抛出到游戏流程。
- 素材完整性：manifest 中每个文件存在、哈希一致、时长合理、循环项元数据完整，运行代码不引用母版目录。
- 回归：现有 engine、presentation、bottle、integration、runtime integrity 和构建检查继续通过。

测试使用 fake driver 验证策略，不依赖测试机器实际扬声器，也不以“听到了”替代契约测试。

### 9.2 浏览器体验验收

- 首次进入不因自动播放限制报错；第一次有效点击后 BGM 正常淡入。
- BGM 长时间循环无明显接缝、节拍跳变或响度突变。
- 所有核心交互的音画同步正确，特别是魔女挥杖、倒液、完成爆发、飞离和消失。
- 快速连续点击时无明显爆音、削波或过度叠加。
- BGM/SFX 开关立即生效，刷新后状态保持。
- 页面前后台切换后只有一条 BGM，且按玩家设置恢复。
- 声音设置浮层不遮挡棋盘，在目标手机视口内无裁切，键盘操作和焦点可用。
- 控制台无应用警告/错误，音频与 UI 素材请求无失败。

### 9.3 完成标准

- 运行音频总包体不超过 2.5MB，或在交付报告中给出经确认的偏差原因。
- 全部自动测试、运行素材校验和生产构建通过。
- 浏览器完整流程试听通过，并记录实际素材时长、格式、体积和已知限制。
- 书面说明 Web 到 Cocos 的替换点，确保后续工程化不把 React 音频实现复制进游戏规则层。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 浏览器/小游戏自动播放限制 | 首次有效用户手势统一解锁；失败可重试且不阻塞游戏 |
| BGM 循环接缝明显 | 生成阶段统一节拍和尾音边界；自动检查后进行真机长循环试听 |
| 快速操作导致声音嘈杂 | cue 冷却、最大并发、优先级淘汰和 BGM ducking |
| 包体过大 | 无损母版不进运行包，运行文件压缩，实施时记录逐文件体积 |
| Web 与 Cocos 行为漂移 | cue/manifest/director 策略平台无关，平台层只负责播放 |
| 单一素材损坏阻断游戏 | 独立加载、静默降级、核心流程不等待音频结果 |
| 延迟消失音污染重开的关卡 | 延迟任务归 director/关卡会话所有，重开和卸载统一取消 |

## 11. 实施顺序建议

1. 以测试定义 cue、manifest、设置和 driver/director 契约。
2. 建立确定性音频生成器，输出无损母版、运行素材、manifest 和报告。
3. 实现 Web audio driver 与 AudioDirector，先通过 fake-driver 单元测试。
4. 在现有结果处理器中接入声音事件和完成时间线。
5. 生成并接入声音设置正式 UI 图片资产与交互浮层。
6. 完成素材完整性、回归、构建和浏览器试听验收。
7. 固化 Cocos/微信小游戏迁移说明，然后再进入小游戏工程化计划。
